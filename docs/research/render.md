# The daw `Render` service: what REAPER exposes, what standalone can do, and the shape to build

Research for [#44](https://github.com/FastTrackStudios/session/issues/44),
under the wayfinding map [#16](https://github.com/FastTrackStudios/session/issues/16),
filed from [#38](https://github.com/FastTrackStudios/session/issues/38).

**Question.** The daw facade has no render service. What does `Render` in
daw-proto look like — render the project or a time selection with a named
preset to an output path, on REAPER over its render config and on standalone
over its offline engine — and how do stems per bus, print-through bounces,
render presets as data and the mastering handoff sit on it?

## Summary

- **REAPER has no "render" API call.** A render is *configure project
  render state, then fire an action*: every knob is a `GetSetProjectInfo`
  (numeric, `SDK.h:3023-3045`) or `GetSetProjectInfo_String` (`SDK.h:3083-3091`)
  key prefixed `RENDER_`, and the trigger is `Main_OnCommand` (`SDK.h:4533`)
  with `42230` "Render project, using the most recent render settings,
  auto-close render dialog" (`ActionList.txt:3002`). Completion is
  observable through `EnumProjects(0x40000000)` = "currently rendering
  project" (`SDK.h:1248`) and results through `RENDER_STATS` /
  `RENDER_TARGETS` (`SDK.h:3087-3089`).
- **The whole REAPER surface is already reachable from the daw facade
  today** — `Projects::run_command` + `get/set_project_info(_string)`
  (`daw/crates/daw/proto/src/project/service.rs:55,65-68`), implemented in
  daw-reaper over `GetSetProjectInfo_String`
  (`daw/features/reaper/daw-reaper/src/project.rs:563-600`) — and a legacy
  FTS driver already rendered this way (`legacy-offline.rs:167-225`). What is
  missing is a *typed* service so callers stop hand-packing bitfields.
- **Standalone has an offline-capable renderer but no render-to-file.**
  `ProjectRenderer::render_block(start_frame, frames) -> StereoBuffer`
  (`standalone/audio_engine/render/mod.rs:416`) is pure math, no threads,
  no cpal (`mod.rs:32-34`), driven by unit tests with no audio device
  (`mod.rs:1387,1410,1533`). Nothing writes a WAV (only a test helper,
  `standalone/audio_engine/source.rs:225`), `run_command` is a no-op
  (`standalone/sync/project.rs:356-361`), and `RENDER_*` keys land in
  ext-state without meaning (`sync/project.rs:412-431`).
- **Presets are already typed as data.** `reaper-config::render_presets`
  parses and round-trips `reaper-render.ini`'s four entry kinds
  (`daw/features/reaper/reaper-config/src/render_presets/types.rs:5-201`);
  nothing consumes it yet (only `reaper-input` depends on the crate,
  `daw/features/reaper/reaper-input/Cargo.toml:44`). A `RenderPreset` in
  daw-proto can be a Facet twin of those structs.
- **One trap for the per-language loop:** standalone's renderer states that
  a VCA lead's *mute button does not mute followers* — only a lead mute
  *envelope* does (`standalone/audio_engine/render/mod.rs:771-777`). The
  loop decided in #38 ("set the language VCAs' mute") must therefore mute
  through the mute gang (`TrackGrouping::mute_lead/mute_follow`,
  `daw/crates/daw/proto/src/track/track.rs:268-269`) or set each source's
  mute directly, not rely on VCA mute propagation.

## 1. What REAPER's SDK exposes for rendering

### 1.1 Numeric render keys — `GetSetProjectInfo(project, desc, value, is_set)`

Signature at `SDK.h:3063`; the documented render keys are `SDK.h:3023-3045`:

| key | meaning (verbatim bit table, abbreviated) | `SDK.h` |
|---|---|---|
| `RENDER_SETTINGS` | `(&(1\|2)==0)`=master mix, `&1`=stems+master, `&2`=stems only, `&4`=multichannel tracks → multichannel files, `&8`=use render matrix, `&16`=mono-media tracks → mono files, `&32`=selected media items, `&64`=selected items via master, `&128`=selected tracks via master, `&256`=embed transients, `&512`=embed metadata, `&1024`=embed take markers, `&2048`=2nd pass, `&4096`=razor edits, `&8192`=pre-fader stems (not if via master), `&16384`=only stem channels sent to parent, `&32768`=preserve source metadata, `&(1<<16)`=preserve start offset, `&(2<<16)`=preserve source sample rate, `&(4<<16)`=selected items/razor edits as a single file, `&(8<<16)`=parallel render via master, `&(16<<16)`=delay render start for FX init | 3023 |
| `RENDER_BOUNDSFLAG` | 0=custom time bounds, 1=entire project, 2=time selection, 3=all regions, 4=selected media items, 5=selected regions, 6=all markers, 7=selected markers | 3024 |
| `RENDER_CHANNELS` | channel count of the rendered file | 3025 |
| `RENDER_SRATE` | sample rate (0 = project rate) | 3026 |
| `RENDER_STARTPOS` / `RENDER_ENDPOS` | custom bounds when `RENDER_BOUNDSFLAG=0` | 3027-3028 |
| `RENDER_TAILFLAG` | which bounds modes get the tail: `&1` custom, `&2` entire project, `&4` time selection, `&8` markers/regions, `&16` selected items, `&32` selected markers/regions | 3029 |
| `RENDER_TAILMS` | tail length in ms (needs `RENDER_BOUNDSFLAG` + `RENDER_TAILFLAG`) | 3030 |
| `RENDER_ADDTOPROJ` | `&1` add rendered files to project, `&2` skip likely-silent files | 3031 |
| `RENDER_DITHER` | `&1` dither, `&2` noise shaping, `&4` dither stems, `&8` noise-shape stems, `&16` disable all | 3032 |
| `RENDER_NORMALIZE` | `&1` enable; `(&14)` algorithm 0=LUFS-I, 2=RMS, 4=peak, 6=true peak, 8=LUFS-M max, 10=LUFS-S max; `&64` brickwall, `&128` brickwall true-peak; `&512`/`&1024` fade in/out; `&16384`/`&32768` trim start/end silence; `&(1<<16)`/`&(2<<16)` pad start/end; `(&(32\|4096\|(16<<16)))` selects "as if files play together" / "to loudest file" / "to master mix" | 3033 |
| `RENDER_NORMALIZE_TARGET`, `RENDER_BRICKWALL` | linear gain (0.5 = -6.02 dB) | 3034-3035 |
| `RENDER_FADEIN/OUT`, `…SHAPE`, `RENDER_FADELPF` | seconds; shape index; LPF fade flags | 3036-3040 |
| `RENDER_PADSTART/END`, `RENDER_TRIMSTART/END` | seconds; linear threshold | 3041-3044 |
| `RENDER_DELAY` | seconds of FX warm-up (needs `RENDER_SETTINGS&(16<<16)`) | 3045 |

So **"stems per selected track"** is `RENDER_SETTINGS & 2` (stems only) or
`& 1` (stems plus master mix) — REAPER's stem source is *the selected
tracks*; the preset parser names the same value "3: Stems (selected
tracks)" (`daw/features/reaper/reaper-config/src/render_presets/types.rs:134`),
and `&128` is the variant "selected tracks via master" (`SDK.h:3023`).
`&8192` renders those stems pre-fader; `&16384` renders only the channels a
stem sends to its parent (`SDK.h:3023`). **Tail** is two keys
(`RENDER_TAILFLAG` gating by bounds mode, `RENDER_TAILMS` the length,
`SDK.h:3029-3030`); **normalise** is `RENDER_NORMALIZE` +
`RENDER_NORMALIZE_TARGET` (`SDK.h:3033-3034`); **add to project** is
`RENDER_ADDTOPROJ & 1` (`SDK.h:3031`).

### 1.2 String render keys — `GetSetProjectInfo_String(project, desc, valuestrNeedBig, is_set)`

Signature at `SDK.h:3094`; render keys at `SDK.h:3083-3091`:

| key | meaning | `SDK.h` |
|---|---|---|
| `RENDER_FILE` | render directory | 3083 |
| `RENDER_PATTERN` | file name, may contain wildcards (`$project`, `$track`, `$region`, …) | 3084 |
| `RENDER_EXTRAFILEDIR` | alternate path for `renderedfile.wav.rpp` and `render_stats.html` | 3085 |
| `RENDER_METADATA` | project metadata, e.g. `"ID3:TALB\|my album"` to set | 3086 |
| `RENDER_TARGETS` | read: semicolon list of files the *current* settings would write | 3087 |
| `RENDER_STATS` | read-only stats of the last render; pass an action id as `valuestr` (e.g. `"42437"`) to run a dry-run first | 3088 |
| `RENDER_STATS_SUMMARY` | human-readable form of the same | 3089 |
| `RENDER_FORMAT` | base64 sink config, **or a bare 4-byte sink id** (`"evaw"` = WAV, `"l3pm"` = MP3) for that sink's defaults | 3090 |
| `RENDER_FORMAT2` | secondary sink, `""` disables | 3091 |

`RENDER_FORMAT` is a *string* key. The legacy driver set it numerically
(`project.set_info("RENDER_FORMAT", 0.0)`, `legacy-offline.rs:188`), which
hits the numeric entry point and is silently wrong — a typed service
removes that class of mistake.

### 1.3 Triggering and observing a render

- `Main_OnCommand(int command, int flag)` — `SDK.h:4528-4533` ("See
  `Main_OnCommandEx`"). daw-reaper's `Projects::run_command` resolves
  numeric or named ids through `named_command_lookup`
  (`daw/features/reaper/daw-reaper/src/project.rs:497-511`).
- Render actions, from REAPER's own export:

  | id | name | `ActionList.txt` |
  |---|---|---|
  | 40015 | File: Render project to disk... (opens the dialog) | 1160 |
  | 41824 | File: Render project, using the most recent render settings | 2734 |
  | **42230** | File: Render project, using the most recent render settings, auto-close render dialog | 3002 |
  | 41855 | …most recent settings, with a new target file name... | 2758 |
  | 41823 | File: Add project to render queue, using the most recent render settings | 2733 |
  | 41207 | Render all queued renders | 2189 |
  | 43349 | File: Dry run render project, using the most recent render settings | 3743 |
  | 42437-42441 | Calculate loudness of selected items / selected tracks / master mix (± time selection) via dry run render | 3167-3171 |
  | 41890-41893 | Region render matrix: render master / all tracks / selected tracks for all regions | 2791-2794 |
  | 40405, 40788, 40892 | Track: Render tracks to stereo/mono/multichannel (post-fader) stem tracks (and mute originals) | 1470, 1799, 1900 |
  | 41716-41721 | Track: Render *selected area* of tracks to stem tracks | 2633-2638 |
  | 40877, 40901, 41223 | Track: Freeze to multichannel/mono/stereo | 1885, 1909, 2204 |

  `42230` is the headless choice (auto-close); `41824` leaves the progress
  dialog up; `40015` is interactive. The `Track: Render tracks to … stem
  tracks (and mute originals)` family (`ActionList.txt:1470-1901`) is the
  **in-project print** — it writes new tracks rather than files, which is
  what a print-through bounce wants (§5.4).
- Completion: `EnumProjects(0x40000000)` returns "the currently rendering
  project, if any" (`SDK.h:1248`) — poll for `NULL`. The legacy driver
  polled `RENDER_SEEKPOS` (`legacy-offline.rs:229-261`); that key appears
  **zero** times in the v7.63 header and zero times in a v7.001 header
  (`grep -c RENDER_SEEKPOS` on both = 0), so it is undocumented and should
  not be relied on.
- Results: `RENDER_STATS` / `RENDER_STATS_SUMMARY` (`SDK.h:3088-3089`);
  `RENDER_TARGETS` predicts file names before rendering (`SDK.h:3087`), and
  `ResolveRenderPattern(project, path, pattern, targets, sz)` expands a
  wildcard pattern to a NUL-separated file list (`SDK.h:5702-5707`).
- Region render matrix: `EnumRegionRenderMatrix(proj, regionindex,
  rendertrack)` (`SDK.h:1261-1266`) and `SetRegionRenderMatrix(proj,
  regionindex, track, flag)` with flag 2 = force mono, 4 = stereo, N = N/2
  channels (`SDK.h:6250-6255`). Not wrapped anywhere in `daw/` today (no
  hits for `SetRegionRenderMatrix` under `daw/features/reaper/daw-reaper/src`
  or `daw/features/standalone/daw-standalone/src`); the region service doc
  only *mentions* "render matrix" (`daw/crates/daw/proto/src/region/service.rs:9`).
- `RenderFileSection(source, target, start_pct, end_pct, playrate)` renders
  a section of a *media file*, "not available while playing back"
  (`SDK.h:5656-5661`) — a file utility, not a project render.
- `CalcMediaSrcLoudness(PCM_source*)` dry-run-renders one source for
  loudness (`SDK.h:304-306`).
- reaper-rs medium wraps only the string *setter*
  (`get_set_project_info_string_set`, `…/main/medium/src/reaper.rs:1621`);
  daw-reaper goes to the low API directly
  (`daw/features/reaper/daw-reaper/src/project.rs:574,591`;
  `safe_wrappers/audio.rs:17-24` for the numeric one).

### 1.4 How a render preset is stored

REAPER keeps presets in `reaper-render.ini` in the resource directory; the
last-used settings live in `reaper.ini` as `rendercfg=<hex sink cfg>`,
`rendercfg2_sz`, `rendercfg_sz`, `renderclosewhendone`
(`~/.config/REAPER/reaper.ini:238-241`). This machine has no
`reaper-render.ini` (none under `~/.config/REAPER/`), i.e. no saved presets.

`reaper-config` already models the file
(`daw/features/reaper/reaper-config/src/render_presets/mod.rs:1-9`,
workspace member `daw/Cargo.toml:79,212`; reachable here as a git dep
`Cargo.toml:160` with a local patch `Cargo.toml:1100`). Four entry kinds
(`types.rs:12-24`):

| entry | line format | fields | `types.rs` |
|---|---|---|---|
| `<RENDERPRESET name srate ch offline_mode use_proj_srate resample cb1 cb2\n  rendercfg_b64\n>` | primary format | `sample_rate`, `channels`, `offline_mode` (0 full-speed offline … 4 offline idle), `resample_mode` (0-9), `various_checkboxes` (dither bits), `various_checkboxes2` (the `RENDER_SETTINGS` bits: `&4`, `&16`, `&256`, `&1024`, `&2048`, `&8192`, `&16384`, `&32768`, `&65536`, `&524288`), `render_cfg` base64 | 26-88 |
| `<RENDERPRESET2 name\n  rendercfg2_b64\n>` | secondary format | `render_cfg` | 90-105 |
| `RENDERPRESET_OUTPUT name bounds start end source unknown filename tail dir tail_ms` | bounds + destination | `bounds` (0 custom, 1 project, 2 time sel, 3 regions, 5 selected regions), `source` (0 master, 1 master+stems, 3 stems (selected tracks), 8 matrix, 32/64 items, 128 selected tracks via master, 4096 razor), `filename` pattern, `tail`, `directory`, `tail_ms` | 107-151 |
| `RENDERPRESET_EXT name normalize_mode normalize_target brickwall fadein fadeout fi_shape fo_shape trim_lead trim_trail pad_start pad_end` | post-processing | `normalize_mode` bitmask matching `RENDER_NORMALIZE`, targets as linear gain | 153-201 |

Parse and serialise round-trip (`mod.rs:19-22`, `serialize.rs:109`). The
`render_cfg` blob is opaque base64 of the sink config — the same bytes
`RENDER_FORMAT` accepts (`SDK.h:3090`) — so a preset can be applied to a
project by writing its fields to the keys above without decoding it.

## 2. What daw-standalone can render offline today

**The engine.** `ProjectRenderer` (`standalone/audio_engine/render/mod.rs:333-354`)
is built from a `Standalone` backend + project GUID + sample rate
(`mod.rs:357`) and exposes `render_block(&self, start_frame: u64, frames:
usize) -> StereoBuffer` (`mod.rs:414-416`). The module doc says what it
honours — item playback with fades/envelopes/play-rate, sends, parent send
to master, track volume/pan (`mod.rs:8-16`) — what is out of scope
(hardware outputs, >stereo at the master, `mod.rs:17-20`), and that it is
"WASM-compatible: pure math + heap, no threads, no cpal" (`mod.rs:32-34`).
It reads a per-revision `RenderSnapshot` (`render/snapshot.rs:33-54`) with a
topological processing order and a solo mask (`render/graph.rs:7-16`,
`snapshot.rs:42-46`).

**It already runs without a device.** Callers are the cpal mixer
(`standalone/audio_engine/mixer.rs:759`), the duplex engine
(`duplex_engine.rs:169`), the web AudioWorklet shim (`web.rs:419`) — and the
in-file unit tests, which call `renderer.render_block(0, 128)` /
`(0, 512)` on a bare `Standalone` (`mod.rs:1387,1410,1533,1539,1545,1580,
1593,1629,1646`). The backend comment confirms the design intent: "a
backend used purely synchronously (offline render, tests) never needs a
runtime" (`standalone/sync/daw.rs:680-682`). An offline master render is
therefore a loop over `render_block` from a start frame to an end frame —
**nothing does that loop today**, and nothing writes the result: the only
WAV writer in the crate is a test helper (`standalone/audio_engine/source.rs:225,253`).

**What the grep for `offline|bounce|export|render_to` finds** is unrelated:
FX bypass-offline state (`standalone/fx.rs:223-234`, `fx_chains.rs:167`,
`project_loader.rs:1263-1264`), the patched `.rpp` export in `save.rs:3,88`,
and the plugin-host note that "tests render offline blocks"
(`vst3_host.rs:974`, `plugin_host.rs:136-138`).

**Stems.** There is no per-track output; `render_block` returns one master
`StereoBuffer` (`mod.rs:416-417`). The snapshot carries the solo mask
(`snapshot.rs:46,80`) and per-track `muted` (`snapshot.rs:109`), so a
per-track stem is reachable today only by soloing that track and rendering
the master — which is REAPER's "selected tracks via master" (`SDK.h:3023`,
`&128`), not a true pre-master stem.

**VCA.** Followers multiply by every shared-group lead's fader and volume
envelope (`mod.rs:771-773,829`) and pan offsets (`mod.rs:835`), but — quoting
the code — "a MUTE ENVELOPE on the lead mutes followers (the lead's mute
button does NOT — mute isn't a VCA parameter)" (`mod.rs:774-777`). The
snapshot folds `vca_follow | vca_prefx_follow` (`snapshot.rs:709`).

**Project-info and commands.** The standalone `Projects` impl:
`run_command` is a no-op returning `false` ("No REAPER action registry on
standalone", `standalone/sync/project.rs:356-361`); `get_project_info_string`
knows `PROJECT_NAME`/`PROJECT_PATH`/`PROJECT_NOTES` and otherwise reads
project ext-state (`sync/project.rs:392-418`); `set_project_info_string`
writes unknown keys into ext-state (`sync/project.rs:420-432`);
`get_project_info` knows only time-signature and BPM, "Unknown keys = 0"
(`sync/project.rs:434-448`). So writing `RENDER_FILE` on standalone
persists a string and renders nothing.

**Time selection** exists on the transport service
(`daw/crates/daw/proto/src/transport/service.rs:69-76`). No project-length
helper was found in the standalone crate (grep for `project_length|
length_seconds|project_end` under `standalone/` returns nothing), so
"entire project" bounds must be derived from the last item end.

**Aux hook.** `AuxRenderer` mixes click/count-in/guide audio into the engine
output *after* the project block (`standalone/audio_engine/aux_render.rs:1-16`)
— an offline render loop can choose to include or exclude it.

## 3. What the daw facade has for render today

**No render service.** Every `render` hit in daw-proto/daw-control/daw-reaper
is a UI-render or renderer comment (`daw/crates/daw/proto/src/dock_host/service.rs:30-31`,
`peak/types.rs:25`, `automation/envelope.rs:69`, `handle.rs:201`,
`region/service.rs:9`, `midi/service.rs:123`, `stretch_marker/types.rs:83`,
`daw/crates/daw/control/src/project.rs:497-522`). No trait named `Render`
exists among the `#[architect::rpc]` traits (`grep "pub trait"` over
`daw/crates/daw/proto/src`).

**The raw surface is wrapped.** `Projects`
(`daw/crates/daw/proto/src/project/service.rs:8-9`,
`#[architect::rpc(ops(ProjectContext as ProjectArg))]`) carries:

- `run_command(project, command: &str) -> bool` (`service.rs:55`)
- `get_project_info_string / set_project_info_string / get_project_info /
  set_project_info` (`service.rs:65-68`), plus `get/set_project_config`
  (`service.rs:69-70`).

daw-control exposes them as `Project::run_command`
(`daw/crates/daw/control/src/project.rs:456-465`) and
`get_info_string / set_info_string / get_info / set_info`
(`project.rs:498-535`) — whose doc comments already name
`"RENDER_FILE"`, `"RENDER_PATTERN"` (`project.rs:497,509`) and
`"RENDER_SETTINGS"` (`project.rs:522`) as the intended keys. daw-reaper
implements them over `low.GetSetProjectInfo_String`
(`daw/features/reaper/daw-reaper/src/project.rs:563-600`) and
`safe_wrappers::get_set_project_info` (`safe_wrappers/audio.rs:17-24`,
used for `PROJECT_SRATE` at `audio_engine.rs:99-101`).

**A prior FTS render driver on this surface.** The legacy sample-collector
rendered through exactly these calls: `set_info_string("RENDER_FILE", dir)`
(`legacy-offline.rs:171-173`), `set_info_string("RENDER_PATTERN", "$region")`
(`:176`), `set_info("RENDER_SETTINGS", 8.0)` for the region matrix (`:185`),
`run_command("42230")` (`:219-224`), then polled for completion
(`:233-261`). It also used `project.regions().set_render_track(...)`
(`:198,206`), which no longer exists in daw-control (no `set_render_track`
under `daw/crates/daw/control/src`) — the matrix wrapper was lost in the
architect port.

**Adjacent services the per-language loop needs**, all present:
`Tracks::selected` (`daw/crates/daw/proto/src/track/service.rs:44`),
`set_muted(project, track, muted)` (`:51`),
`set_group_membership(project, track, slot, member)` (`:112-118`),
`set_selected` (`:122`); `Track.muted` / `.selected`
(`daw/crates/daw/proto/src/track/track.rs:86,92`); `TrackRef::{Guid, Index,
Master}` (`track.rs:13-20`); `TrackGrouping` with `mute_lead/mute_follow`
and `vca_lead/vca_follow/vca_prefx_follow` (`track.rs:263-282`);
`Transport::get_time_selection -> Option<LoopRegion>` and
`set_time_selection(project, start, end)`
(`daw/crates/daw/proto/src/transport/service.rs:69-75`).

**Constraint on the shape:** `#[architect::rpc]` methods take at most 4
params (Facet) (`CLAUDE.md:224`; `daw/CLAUDE.md:223`).

## 4. Existing FTS render code and the spec's needs

**This repo has no audio-render code.** Under `crates/session` every
`render` hit is Dioxus/UI (`crates/session/ui/src/components/mod.rs:3`,
`signals.rs:13,228-269`, `layouts/performance.rs:98-255`, …). Two
non-UI mentions matter conceptually: `mix_phases.rs:20-26` — offline mix
steps "are not realtime plugins — they are renders, and the result is
written back to the item" (the print-through idea, as mix state); and
`crates/session/proto/src/guide.rs:6` — the guide engine "renders count-in
and section cues as audio". `features/reaper/session-extension` has zero
hits. `features/dynamic-template` hits are classification keywords
("export", "render", "rendered" → the Reference folder,
`features/dynamic-template/dynamic-template/src/groups/reference/mod.rs:62-65`),
a bus-tree "render" (`buses.rs:452`), and a warning that the typed model
"silently dropped … every RENDER_*/RECORD_CFG setting" so the organiser
edits the raw chunk tree instead (`main.rs:524-528`) — i.e. the template
tool deliberately *preserves* a project's render settings.

**The spec.** `docs/spec/session/workflows.md`:

- `flow.vocals.language.render` (`:629-633`): "Rendering the project
  renders **one version per language**: each render with that language's
  VCA up and the others muted, the language-free tracks in every one,
  named for the language. The active language does not have to be changed
  to render the others."
- Languages are "muted through their VCA — one VCA per language, `VOX EN`,
  `VOX ES`, `VOX PT`" (`:620-622`); the golden session lists those VCAs
  "and a render per language" (`:707-713`); the Vocals row of the table
  tracks "render per language" (`:30`).
- `flow.scenes.render` (`:79-82`) is the other sense of the word — a scene
  *picture* rendered headless as a test fixture — not audio.
- Print-through: "a synth that was printed keeps its MIDI under it as a
  layer" (`:765-772`).
- Stems: "Stems are the three buses" (`docs/spec/session/maximal-template.md:68`);
  in live routing, song projects "send stems to loopback channels"
  (`routing-project.md:3-4,10-20`); a "Stem Split/" reference folder and
  "mix / reference / bounce / master" classification
  (`track-organization.md:24-25,54-63`).
- "Mastering handoff" appears only in the map (#16, "Rendering: one version
  per language, stems per bus, print-through bounces, render presets, the
  mastering handoff") and #44 — nowhere in the spec yet.

## 5. Recommendation

### 5.1 The `Render` service in daw-proto

One `RenderJob` value per call keeps every method at ≤ 2 params
(`CLAUDE.md:224`); all types `#[derive(Facet)]` like the rest of daw-proto
(`daw/crates/daw/proto/src/transport/transport.rs:12,23,32`).

```rust
// daw/crates/daw/proto/src/render/service.rs
#[architect::rpc(ops(ProjectContext as ProjectArg))]
pub trait Render {
    /// Render `job` and return the files written (+ stats when the
    /// backend has them). Blocks until the render is finished.
    fn render(&self, project: ProjectContext, job: RenderJob) -> DawResult<RenderReceipt>;
    /// Files `job` *would* write — REAPER: RENDER_TARGETS / ResolveRenderPattern.
    fn targets(&self, project: ProjectContext, job: RenderJob) -> DawResult<Vec<String>>;
    /// Loudness of `job` without writing — REAPER: RENDER_STATS + dry-run action.
    fn dry_run(&self, project: ProjectContext, job: RenderJob) -> DawResult<RenderStats>;
    /// The DAW's stored presets as data — REAPER: reaper-render.ini.
    fn presets(&self) -> Vec<RenderPreset>;
    fn save_preset(&self, preset: RenderPreset) -> DawResult<()>;
    /// Progress of the running render — REAPER: EnumProjects(0x40000000).
    #[subscribe]
    fn progress(&self) -> Stream<RenderProgress>;
}
```

```rust
// daw/crates/daw/proto/src/render/types.rs
pub struct RenderJob {
    pub preset: RenderPreset,            // format + quality + post, AS DATA
    pub bounds: RenderBounds,
    pub source: RenderSource,
    pub output: RenderOutput,
}
pub enum RenderBounds {                  // RENDER_BOUNDSFLAG (SDK.h:3024)
    EntireProject, TimeSelection, Custom { start_seconds: f64, end_seconds: f64 },
    AllRegions, SelectedRegions, SelectedItems, AllMarkers, SelectedMarkers,
}
pub enum RenderSource {                  // RENDER_SETTINGS low bits (SDK.h:3023)
    MasterMix,
    /// One file per track. `tracks` is explicit — the service selects
    /// them; callers never depend on the user's selection.
    Stems { tracks: Vec<TrackRef>, with_master: bool, pre_fader: bool, parent_channels_only: bool },
    TracksViaMaster { tracks: Vec<TrackRef> },
    RegionMatrix,
    SelectedItems { via_master: bool, single_file: bool },
}
pub struct RenderOutput {
    pub directory: String,               // RENDER_FILE (SDK.h:3083)
    pub pattern: String,                 // RENDER_PATTERN (SDK.h:3084)
    pub add_to_project: bool,            // RENDER_ADDTOPROJ &1 (SDK.h:3031)
    pub skip_silent: bool,               // RENDER_ADDTOPROJ &2
    pub tail_ms: Option<u32>,            // RENDER_TAILFLAG + RENDER_TAILMS (SDK.h:3029-3030)
    pub secondary: Option<RenderFormat>, // RENDER_FORMAT2 (SDK.h:3091)
}
pub struct RenderPreset {                // mirrors reaper-config types.rs:36-201
    pub name: String,
    pub format: RenderFormat,            // Wav{bit_depth}, Flac{..}, Mp3{..}, Raw{sink_cfg_b64}
    pub sample_rate: Option<u32>,        // None = project rate (RENDER_SRATE=0)
    pub channels: u32,
    pub resample_mode: u32, pub offline_mode: u32,
    pub dither: Dither,                  // RENDER_DITHER (SDK.h:3032)
    pub normalize: Option<Normalize>,    // RENDER_NORMALIZE + _TARGET (SDK.h:3033-3034)
    pub limiter: Option<Brickwall>,      // RENDER_NORMALIZE &64/&128 + RENDER_BRICKWALL
    pub fades: Fades, pub trim: Trim, pub pad: Pad,
    pub flags: u32,                      // remaining RENDER_SETTINGS bits, passthrough
}
pub struct RenderReceipt { pub files: Vec<String>, pub stats: Option<RenderStats> }
pub struct RenderProgress { pub fraction: f32, pub file: Option<String>, pub done: bool }
```

`RenderFormat::Raw { sink_cfg_b64 }` keeps the opaque sink blob a preset
already carries (`types.rs:86-87`) so REAPER presets round-trip losslessly;
the named variants map to the bare 4-byte sink ids `RENDER_FORMAT` accepts
(`"evaw"`, `"l3pm"`, `SDK.h:3090`) for defaults.

### 5.2 REAPER implementation (daw-reaper)

`render(job)` =

1. Snapshot the current `RENDER_*` values (so the user's dialog state is
   restored afterwards; the action reads *project* state, `ActionList.txt:3002`).
2. Set numeric keys via `GetSetProjectInfo` (`SDK.h:3023-3045`) and string
   keys via `GetSetProjectInfo_String` (`SDK.h:3083-3091`) from `job`;
   for `Stems { tracks }` call `Tracks::set_selected` on exactly those
   tracks first (stems = selected tracks, `types.rs:134`, `SDK.h:3023`).
3. `Main_OnCommand(42230)` (`SDK.h:4533`, `ActionList.txt:3002`) via the
   existing `run_command` path (`daw-reaper/src/project.rs:497`).
4. Wait while `EnumProjects(0x40000000)` is non-null (`SDK.h:1248`) — the
   documented completion signal — publishing `progress` from the same
   pump; do **not** use `RENDER_SEEKPOS` (undocumented, §1.3).
5. Read `RENDER_STATS` (`SDK.h:3088`) into the receipt; restore step 1.

`targets` = write keys, read `RENDER_TARGETS` (`SDK.h:3087`), restore.
`dry_run` = write keys, `RENDER_STATS` with `valuestr="43349"` (dry run,
`ActionList.txt:3743`; the `valuestr` action hook is documented at
`SDK.h:3088`). `presets` = parse `reaper-render.ini` with
`reaper_config::RenderPresetFile::parse` (`render_presets/mod.rs:19-22`) and
map `RenderPreset`/`RenderPresetOutput`/`RenderPresetExt` triples by name
into the daw-proto `RenderPreset`; `save_preset` serialises back
(`serialize.rs:109`). daw-reaper would gain a dep on `reaper-config`
(today only `reaper-input` has one, `daw/features/reaper/reaper-input/Cargo.toml:44`).

### 5.3 Standalone implementation (daw-standalone)

`render(job)` = resolve bounds to `[start, end)` frames (time selection from
`Transport::get_time_selection`, `transport/service.rs:69`; entire project
from the last item end — helper to add, §2), extend by `tail_ms`, then loop
`ProjectRenderer::render_block(start, block)` (`render/mod.rs:416`) with no
device — the pattern the tests already use (`mod.rs:1387`) — into a WAV
writer (hound or the `fts-sample` encoder; the crate has none today,
`source.rs:225` is test-only). `MasterMix` is that loop. `Stems { tracks }`
is one loop per track with the snapshot's solo mask set to that track
(`snapshot.rs:46`) — equivalent to REAPER's "via master"; a true pre-master
stem needs `render_block` to expose per-track buses (they exist inside the
block as `buses[ti]`, `mod.rs:801`). Normalise/limit/fade/trim/pad are a
post-pass over the buffer. `presets` come from a standalone preset store
(ext-state or a styx file). `progress` publishes per block on a PubSub hub
like the meter pump (`sync/daw.rs:675-682`). Everything stays in
`audio_engine/` under the platform rules (no threads, no I/O in the
renderer; the WAV writer lives in the adapter).

### 5.4 How the map's other needs sit on it

| need | on `Render` | notes |
|---|---|---|
| render whole project / time selection with a preset to a path | `render(job)` with `bounds` + `preset` + `output` | §5.1 |
| stems per bus | `RenderSource::Stems { tracks: <bus TrackRefs> }` | the caller (session) picks the bus tracks; REAPER selects them, standalone solos them |
| print-through bounces | *not* `Render::render` — it is REAPER's `Track: Render tracks to … stem tracks (and mute originals)` (`ActionList.txt:1470-1901`) which writes tracks, not files; the printed synth "keeps its MIDI under it as a layer" (`workflows.md:771-772`) | expose as `Render::print(project, tracks, PrintMode)` later, or as a session action over `run_command`; standalone would render the stem and `add_to_project` it under the source |
| render presets as data | `RenderPreset` + `presets()/save_preset()` | REAPER backend reads/writes `reaper-render.ini` through `reaper-config` |
| mastering handoff | `render(job)` with `Stems`/`MasterMix`, `preset` = a 24/32-bit WAV at project rate, `normalize: None`, `tail_ms: Some(...)`, `RenderOutput.pattern` naming the version | a session-side recipe, no new service surface; nothing in the spec defines it yet |

### 5.5 The per-language render loop (a caller, session-side)

Given the decision in #38 and `flow.vocals.language.render`
(`workflows.md:629-633`), the loop lives in the session crate (or a
`features/` crate) over `daw-control`, not inside `Render`:

```text
for language in languages:
    saved = tracks.all(project)                            # Track.muted (track.rs:86)
    for other in languages - {language}:
        mute other's sources                               # see below
    render(project, RenderJob {
        preset: <session preset>, bounds: EntireProject,
        source: MasterMix (or Stems { tracks: buses }),
        output: RenderOutput { pattern: "$project - {language}", .. },
    })
    restore muted flags from `saved`                       # Tracks::set_muted (service.rs:51)
# the active language (scene + VCAs) is never touched
```

"Mute other's sources" must not assume VCA-lead mute propagates: standalone
documents that only a lead mute *envelope* mutes followers
(`render/mod.rs:774-777`). Two safe ways: (a) make each language VCA also a
mute-gang lead (`TrackGrouping::mute_lead`, `track.rs:267`, set through
`set_group_membership`, `service.rs:112`) so `set_muted` on the VCA mutes
its sources on both backends; or (b) mute the language's source tracks
individually (the language dimension knows them). (a) keeps the spec's
"muted through their VCA" (`workflows.md:620`) literal; whether REAPER
propagates VCA-lead mute itself is not settled by any source read here and
should be checked in a `#[reaper_test]` before choosing.
